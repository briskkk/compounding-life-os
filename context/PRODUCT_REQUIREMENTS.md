# 产品需求基线

Web 产品定位为桌面财富终端，交互与信息密度以 1280px 及以上桌面视口为验收范围。手机端体验由第 9 节的独立 App 承担，不要求 Web 页面为手机浏览器牺牲金额精度、表格信息或桌面排版。

## 1. 初始化与家庭作用域

用户通过 `npm run db:init` 创建空白家庭空间，然后建立账户、资产目录和第一笔流水。所有家庭业务数据必须带 `familyId`，VIEWER 只能读取。

验收基线：

- 未初始化时页面给出明确引导，而非静默创建演示数据。
- 当前成员只能看到所属家庭数据。
- 会话切换、写操作和关键系统动作进入审计链。

## 2. 账本与现金闭环

用户可以录入、CSV 导入、筛选、导出和冲正流水。证券买卖可通过账户配置生成同币种现金结算腿。

验收基线：

- BUY/SELL 金额等于数量乘单价，禁止超卖。
- DEPOSIT/WITHDRAW 只能作用于现金资产。
- VALUATION 只用于房产或手动估值资产。
- 冲正保留原记录、标记 `voidedAt`、创建 REVERSAL，并联动作废结算腿；不物理删除历史。
- 内部结算腿和转账不计入外部净投入。

## 3. 财富与持仓

系统重放有效流水，按账户和资产形成持仓，再按实时行情、官方净值、手动估值、面值或成本回落估值。

验收基线：

- 剩余成本采用移动平均成本法。
- 净资产 = 总资产 − 总负债。
- 可自由投资 = 现金与可交易组合资产；房产、手动估值的非黄金资产和华为员工持股不进入该口径。GOLD 恒为可交易黄金，即使采用手动估值也进入该口径。
- 外币资产按当前 USD/CNY、HKD/CNY 汇率折算展示；成本和市值使用同一当前汇率，价格盈亏不夹带汇率波动。
- 页面能说明价格来源与估值新鲜度。

## 3.2 运营事件与导入证据

公司行动和批量导入必须保留事件来源，同时仍由交易流水承载财务影响。

验收基线：

- 拆合股、换股、分拆、转托管、现金分配和基金红利再投展开为可冲正流水；公司行动记录本身不直接改变持仓。
- CSV 支持自动与手工列映射、逐行检查/修正/排除、批次汇总和跨文件语义去重。
- 内部份额/成本调整不在通用手工流水表单开放，避免绕过证据包。

## 3.1 家庭财富总览

总览是桌面财富驾驶舱，先回答家庭财富结果及其变化原因，再提供趋势、构成、状态和目标入口，不用低信息量卡片重复其他一级页面。

验收基线：

- 首屏同时展示净资产与可投资资产，并用“期初可投资资产 + 净投入 + 投资收益 = 当前可投资资产”解释所选自然周、月或季度的变化。
- 利润贡献与周期复盘同口径；只展示真实标的贡献，无法归属的残差单列为待对账差额，不分摊给任何标的。
- 财富轨迹、可投资资产构成、估值覆盖、待确认净值、集中度、在途资金和主 FIRE 方案在同一桌面信息架构中可见。
- 状态速览只陈述可核验事实，不生成自动调仓或买卖建议；在途资金属于资产状态，不进入利润贡献排名。
- 1280px 及以上桌面视口保持核心金额与对账公式单行，不为移动网页压缩信息密度。

## 4. 行情与基金估值

默认行情链为腾讯、天天基金、Sina。PriceBar 保存历史价格；场外基金历史只保存官方净值，盘中估值另表保存并可用官方净值校准。

验收基线：

- 真实链失败不得回落模拟价；`simulated` 仅在显式配置的 E2E/离线环境使用。
- 基金今日官方净值公布后使用官方值；未公布且具备新鲜输入时可展示内部估值，并标明 `FUND-ENGINE`。
- `FundEstimate` 不覆盖官方 `PriceBar`；`FundCalibration` 保留估算与官方结果的误差。
- 基金交易规则可保存来源可核验的申购费率、赎回阶梯和暂停申购窗口；费率只作参考，实际成交费不自动覆盖。
- 场外基金申购当日尚无官方净值时，可先按申购金额记入账本；净值与份额保持待确认，不使用伪造估算份额。该记录必须联动现金，金额作为在途资产计入可投资口径，官方净值到达后通过冲正链替换为正式份额。
- 行情源成功率、延迟和错误按日持久化；跨源价差检查只提示并留审计证据，不自动切换来源或覆盖价格。

## 5. 绩效、风险与看盘

看盘页提供组合当日盈亏、盘中曲线、区间收益、TWR、XIRR、最大回撤、波动率、夏普与四个基准指数对比。

验收基线：

- TWR 消除外部出入金影响；XIRR 表达资金加权年化。
- 无新行情、休市和纯资金流快照不能伪装成新的收益观察点。
- 历史曲线显示估值状态、覆盖率和缺口，而不是假装数据完全结算。

## 5.1 数据结算与核对闭环

总览、看盘和账户页必须使用同一套实时估值与可复核快照证据，但不在每个页面重复技术结构。数据健康中心负责完整诊断、运行证据和安全修复入口。

验收基线：

- 总览只显示一句数据结论，看盘保留低权重状态行，只有缺报价或历史结算缺口时才突出提醒；覆盖率、结算状态和 `PARTIAL` 明细在健康中心展示。
- 行情刷新和派生快照重建进入审计时间线；重建快照不得修改交易流水。
- 账户外部余额核对保存账单余额、账本派生余额、差额、来源与日期的追加凭证，不直接改变账户余额。
- 基金预计到账日到达后可确认外部到账；确认只留证据，实际金额不一致时必须冲正并重录。
- 健康中心可以执行安全修复和跳转到纠错流程，不自动补流水、改估值或生成交易。

## 6. FIRE、储蓄与配置

目标支持一次性目标和退休现金流模式。FIRE 模拟同时评估积累达标和退休后不断供；储蓄记录、收益/波动假设参与情景分析。

验收基线：

- 目标可以使用净资产或可自由投资口径。
- 模拟结果可复现，使用确定性种子和协方差建模。

## 6.1 周期复盘

用户可以按日、本周、本月和本季度回看可投资组合。按日支持选择任意不晚于今日的自然日；按月支持任意已结束或进行中的自然月。所选区间的结果桥、归因、时点、交易、风险、期末在途状态与已保存笔记必须对齐。

验收基线：

- 组合结果同时展示收益金额、TWR、资金体验、净投入、期初/期末资产和可选基准超额。
- 标的、来源、资产类别贡献可切换；无法归属部分单独列为带状态的“待对账差额”，不进入贡献排名；申购待确认与赎回待到账另列为资产状态，明确不属于利润贡献。
- CLOSED/NO_UPDATE/FLOW_ONLY 不进入每日盈亏统计；风险页必须展示估值覆盖与缺口。
- 交易回看只陈述建仓/加仓/减仓/清仓及之后区间表现，不生成自动买卖建议。
- 用户可保存草稿或完成复盘；记录按 family scope 隔离，VIEWER 只读，写操作进入审计链。
- 历史月份使用完整自然月（月初至月末），当前月截至今日；未来或非法月份回落当前月，不得把当前实时报价、当前资金流或当前在途状态注入历史月份。

## 7. 运维与可恢复性

本地、生产、E2E 使用独立 Next dist 目录；E2E 使用独立种子数据库。支持 SQLite 一致性备份、恢复前自动备份和 Docker/腾讯云部署。

## 8. 身份认证（实施中，见 context/PLAN_AUTH_MOBILE.md）

成员使用账号密码登录；网页走服务端会话 cookie，移动端走 Bearer token（双通道共用 Session 表）；不再有无密码的"成员切换身份"。

## 9. 移动端 APP（独立新建项目，另行排期）

让家庭在手机上查看与记录财富，复用现有 API 与引擎。计划：

- 只读查看：持仓、区间绩效、月度汇总趋势、实时报价与分时、资产构成（现有 API 已覆盖，认证通道见第 8 条）。
- 写操作（后续）：流水录入、目标/储蓄更新 —— 需把 Server Actions 核心逻辑抽成 service 层并暴露 POST API。
- 补齐深链路端点：持仓明细、单笔流水、基金估值详情、FIRE 详情、审计查询。
- 移动端特有：推送通知（净值/目标提醒）、弱网分页、离线缓存。
- 实施方式：独立新建项目/仓库，通过本系统 `/api/*` 与双通道认证（Bearer token）对接，不在本仓库内开发。

验收基线（承诺时生效）：

- APP 登录使用用户级 token，家庭数据按 familyId 隔离，RLS 不因 API 通道被绕过。
- APP 展示的数字与网页同源（同一引擎），不出现两套口径。
- 写 API 与 Server Actions 共享同一业务层与审计链。
