# AI 工作协议

## 开始任务

1. 依次读取 `context/PROJECT_OVERVIEW.md`、`CURRENT_STATE.md`、`DECISIONS.md` 和 `CODEBASE_MAP.md`。
2. 根据任务读取相关产品、领域、架构、工程规则、ADR、代码和测试；不得仅凭文件名或本上下文猜实现。
3. 先检查工作区状态。现有未提交修改属于用户，避免覆盖和顺手整理无关文件。
4. 对外部 API、框架当前行为或高风险事实不确定时，查官方一手资料；不得用记忆填空。

## 修改前

在内部或进度说明中确认：任务目标、涉及模块、必须遵守的决策、风险和验证方式。小型明确任务可以直接执行，不需要把流程变成长篇仪式。

如任务与 Accepted ADR 冲突，不得静默选择新方案。应指出冲突；如果用户确实要求改变决策，按 `DECISIONS.md` 的替代协议处理。

## 实施中

- 以最小必要上下文定位代码，再沿 import、调用和测试关系扩展阅读。
- 保持账本、家庭作用域、真实行情、基金数据隔离和财务口径不变量。
- 不修改无关文件，不覆盖用户改动，不提交数据库、密钥、备份或生成目录。
- 数据库变更同步双 schema、迁移、RLS/搬迁脚本和测试。
- 行为变化补测试；先验证最小相关测试，再按风险运行完整门禁。

## 完成任务

1. 检查 diff 是否只包含授权范围，运行 `git diff --check`。
2. 报告结果、关键设计选择、修改文件、验证命令和未解决风险。
3. 若项目事实、架构决策、完成度或下一步发生变化，更新 `CURRENT_STATE.md`、`DECISIONS.md`/ADR 和 `CHANGELOG_AI.md`。
4. 纯局部修复、格式或注释变化不强制制造无意义的状态日志。

## 任务上下文包

复杂任务优先基于 [TASK_PACK_TEMPLATE.md](TASK_PACK_TEMPLATE.md) 建立短期任务包。任务包只引用必要文件，不复制整套稳定上下文，也不能把候选方案写成已确认事实。
