# 三项核心能力实施设计

> 2026-10-10：用户已撤回组合穿透与风险图谱、投资策略实验室，正式模块已删除；家庭财务规划仍暂缓。本任务包为历史设计，不再授权实施后文的研究功能。以 [ADR-042](../../docs/adr/042-remove-research-modules.md) 为准。

历史产品路线：[roadmap](../../docs/roadmap-2026-10-09.md)。静态原型只作设计留档，不连接数据库、不作为当前功能或正式算法验收证据。资产详情独立保留产品持仓和公告，见 [资料说明](../../docs/product-information.md)。

## 当前基础与相关决策

- `src/lib/queries.ts`：loadEngineState 读取真实资本、持仓、在途和负债；loadGoals 装配已有目标，不重复实现它的财富口径。
- `prisma/schema.prisma`：Goal、SavingsEntry、CashPlan 已有；实施前缺多目标共用预算、版本化披露和正式情景模型；旧披露及冻结实验表已停用，仅保留档案/迁移兼容。
- `src/lib/engine/savings.ts`：月度记录优先于周记录；未记录月份不能作为已知零收入/零支出。
- `src/lib/engine/goal-scope.ts`：STREAM 使用 NET_WORTH；退休总资本与可支付现金分开呈现。
- `src/lib/market/fund-holdings.ts`：现有画像主要服务盘中估值，持仓权重占基金净值；24h 缓存并非可审计披露仓库。
- `src/lib/engine/investment-history.ts`、`decision-events.ts`：长期结果、输入水位和无前视事件观察可复用。
- `src/lib/engine/counterfactual.ts`：被 Git 忽略的个人实验；存在与正式规则不同的策略、缺汇率默认值及期末价格回退。保留原文件，不作为已交付基础，不直接用于新模块。
- ADR-001/003/006/010/016/017/021/022/027/033/034/035：账本事实、双财富口径、绩效、派生缓存、计划与证据、反事实、市场归属和现有 UI 规范继续有效。

## 共用基础：复用装配，避免新事实库

1. **事实输入**：先按家庭权限派生不可编辑的资本与持仓；包含估值时点、币种、在途、缺口和来源。开始日期未覆盖的历史事实不得以今天数据代替。
2. **证据标识**：沿用稳定输入摘要与算法版本，扩展为模块局部 evidence ID、来源日期、覆盖/限制。先写共享类型和规范化函数，不建设泛化事件平台或自动引入通用新表。
3. **计划/披露分层**：家庭假设为家庭数据；公募披露和证券身份可全局复用；用户补充的风险关联为家庭数据。全局披露不能夹带家庭仓位。
4. **结果只派生**：保存参数、规则版本、用户判断及不可编辑的当时证据；重算结果不成为余额、持仓或收益事实。计算模块仍为纯函数。
5. **边界**：写操作经 shared service、Zod、requireWrite、审计；新增模型同步 SQLite/PG、RLS、迁移、搬迁与备份。公式或财富口径若需改变 Accepted ADR，单独提出替代 ADR。

## 阶段 A：家庭财务规划首期

### 交付结果

在目标域中完成“未来 24 个月现金支付能力 + 多目标资金竞争 + 两方案比较”。用户能定位首次缺口、受影响目标和造成差异的假设。

### 输入与规则草案

- 账本派生当前现金、已确认证券、在途、长期资产和负债，按已确认用途判断可动用现金。不能把全部 investable 当作现金。
- 用户显式设置必要支出、收入日程、贷款付款、安全储备、目标优先级和到期事项。已有收支与 CashPlan 可作为候选输入，由用户选择引用，保存来源引用防止重复叠加。
- 场景变化描述具体月份与持续期：收入中断、支出变化、一次性目标支出、用户指定的资产兑现。首期 CNY 计划，外币换算沿用资本证据，未来 FX 需单独声明假设。
- 每月现金桥：期初现金 + 计划外部收入 + 指定兑现到账 − 生活支出 − 负债现金偿付 − 消费性目标支出 = 理论期末现金。低于零为融资缺口，不意味着自动借款。
- 目标须区分**消费付款**与**资金预留**。消费付款降低现金；资金预留降低可分配额而不降低账户现金。同一资产或结余可分配一次；退休资金预留不能当作消费支出。
- 本金偿付与利息分开：现金支付相同，但对净资产影响不同；首期不伪造完整未来资产负债表。买房现金支出不能自动生成房产市值，投资买卖和资产兑现不能计为额外财富收益。
- 若目标按期付款后破坏储备或产生负余额，展示金额与月份，并把方案标为有约束缺口；模型不能通过自动卖出/推迟/降目标消除问题。
- 未填写必要输入时为待补假设，计算不可标为完整可行。历史收支不足 3 个有效月时，不能用“可持续”描述系统估出的收入/结余。
- 已有 FIRE 投影继续独立工作；月度现金验证不静默改变退休 NET_WORTH 口径或长期综合回报假设。

### 页面与服务草案

- 目标域二级“家庭规划”，建议 URL `/goals/planning`；先保留 `/goals` 已有测算。
- 首屏方案比较和资金缺口；随后现金路径、目标冲突与逐月桥；假设编辑和证据详情可展开。
- 建议纯引擎 `src/lib/engine/household-plan.ts`，规范化装配 `src/lib/household-plan-data.ts`；先做只读试算，再实现情景保存。
- 候选家庭模型 PlanningScenario 保存假设/来源引用/版本，目标分配关联 Goal；最终模型在 schema 变更前核验，不写 Transaction。
- 首期两个方案，不同时引入概率模拟、全寿命精细税费或自动优化器。

### 开发切片

1. A1：类型、现金桥、预留分配及双方案差异纯引擎，建立守恒与缺输入测试。
2. A2：真实资本装配和日期/来源证据，区分现金、在途和可变现资产。
3. A3：接入家庭规划页面，编辑假设、比较、逐月查看；VIEWER 可临时试算但不保存。
4. A4：情景保存、审计、重算提示与跨家庭测试；不得隐式更新现有 Goal。

### 验收

1. 一笔结余不能供两个目标重复分配；重新排序目标可解释受影响对象，但不改现金事实。
2. 预留不减少现金余额，消费付款才减少；本金还款不误作投资亏损。
3. 输入收入中断后，缺口能定位到月份和事件；恢复收入后路径连续。
4. 在途不到期不作为即时现金；长期资产无兑现计划时不自动补缺口。
5. 空家庭、缺支出、只读、失败保存、家庭切换和旧证据重算各有明确状态。

## 阶段 B：组合穿透首期

### 交付结果

在资产域中展示当前基金/ETF 与直接持股合并后的底层暴露、重复来源及未知比例。先选家庭真实持有的一批高价值产品，不做全市场覆盖承诺。

### 证据与计算草案

- 披露对象记录证券身份、报告期、公告可得日期、取得时间、出处、完整/前十大范围、权重分母与版本。历史分析只能使用当时已公开的版本。
- 现有 Eastmoney 画像可生成候选数据；正式证据需要保留出处、原报表版本及可核验权重，不能把第三方缓存称为官方全量披露。
- 底层金额 = 当前产品持仓价值 × 披露权重，标为按披露估算。直接持股、基金内现金、未穿透部分均纳入守恒分桶，不把未知自动分到股票或现金。
- 联接基金/FOF 递归穿透须乘沿途权重，限制深度、检测循环；缺子基金披露转为未知，避免同时保留父价值和完整子价值重复累计。
- 同一底层证券用稳定身份映射合并；不同上市股份类别的企业关联另行展示，不随意并成相同证券。
- 首期提供公司/资产类别暴露，行业和国家映射不足时保留未知。家庭就业、分红和长期持股共同依赖由用户确认，不推断工资或风险概率。

### 开发切片与验收

1. B1：证据契约、披露输入预检与证券映射；用户确认后保存证据，不能写份额。
2. B2：暴露引擎、残差桶、联接权重、循环/过期/部分披露边界。
3. B3：资产域二级“风险穿透”，建议 URL `/positions?view=exposure`；最大暴露、来源拆分、未知明细。
4. B4：当前持有产品证据接入与家庭风险关联，补只读、来源日期和跨家庭测试。

守恒：直接暴露 + 穿透已知 + 基金内已知现金 + 未知 = 所选组合市值。两种权重分母禁止混乘；前十大不能补足为全量；任何结果可点回具体披露。现有盘中估值、报价和绩效不因穿透写入而改变。

## 阶段 C：策略实验室首期

### 交付结果

在复盘域比较同一可投资范围与同一资金流下的实际路径、冻结起始持仓路径及决策路径差额。冻结期初持仓为正式首个模板，用户规则组合后续再做。

### 规则草案

- 起点按所选日期的真实持仓、现金和在途证据重放。未知份额、缺起点行情或不可解释公司行动时降级或 BLOCKED，不能从当前仓位反推过去。
- 后续主动 BUY/SELL 不执行；外部新增资金留现金，提款先用现金且不足明确失败；分红留现金；应适用于冻结持仓的公司行动按来源事件应用。
- **实际分红金额不直接套到反事实份额**，须有每份分红/权益事件；份额与价格复权口径成对校验，不能前复权价格再重复累计同一分红/拆分收益。
- 费用区分实际主动交易费、与资产持有有关费用及模板执行费用，规则显式说明；同一外部出入金只计算一次。
- 缺历史 FX 不回退 1，缺起点/期末价格不使用未来首价。路径含资格、版本和证据水位，差额称“决策路径差额”。
- 保存模板参数与用户备注，不写 Transaction/Snapshot/PriceBar。个人实验 `counterfactual.ts` 保持原样；建议新正式模块 `frozen-holdings.ts`，避免 Git 忽略造成交付遗漏。

### 开发切片与验收

1. C1：冻结持仓规则、逐日现金/数量与资格纯引擎；用完整与缺口样本验证。
2. C2：历史装配、公司行动和每份分红证据、输入摘要；同区间实际路径复用既有引擎。
3. C3：复盘域二级“策略实验室”，建议 URL `/review/experiments`；展示双路径、差额与规则明细。
4. C4：情景参数保存与交易理由关联；之后再做带生效日期的政策基准。

验收覆盖非零期初持仓、部分/全部卖出、资金提款不足、分红份额不同、拆分/分拆、待确认申购、外币、缺价格、冲正和无前视。正式引擎逐日守恒；输入证据不完整时不可输出完整收益比较。

## 实施与验证门禁

开发顺序建议为 A1→A4、B1→B4、C1→C4；三项方向都已确认，顺序可根据实际使用调整。共用的是事实装配、证据契约和保存边界，不用一个万能引擎统一三个不同问题。

设计交付后先进入 A1 的计算规则和引擎，再接真实页面。每阶段有独立可验收结果，日期工期在切片确定后估算。本次仅确认方向并形成设计/演示，不视为正式模块已经开通。

- 引擎改动：针对性成功/边界/守恒测试，然后 `npm test`。
- UI/API/schema 改动：`npm test`、`npm run build`、`npm run test:e2e`；同步 schema/RLS/备份搬迁与作用域检查。
- 文档与独立预览：路径核验、预览交互/金额一致性、1280/1440px 无溢出、截图复核、`git diff --check`。
- 更新 CURRENT_STATE 的方向/阶段状态、实际完成后再记完成证据；设计草案不标成 Accepted ADR。
