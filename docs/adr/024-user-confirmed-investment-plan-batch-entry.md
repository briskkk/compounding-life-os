# ADR-024：定投管理允许用户核对实际申购后批量录入账本

## 背景

ADR-023 的计划—账本核对能显示执行差额，却不能解决每日重复录入多只基金的操作负担。用户明确要求自动录入或在定投页快速录入。仅凭计划节点自动生成 `BUY` 会把可能未执行、金额不同或净值日顺延的申购当作已发生事实。

## 决策

1. 计划本身仍不自动下单或自动生成流水；未核对的节点不改变现金、持仓、净投入或收益。
2. 定投页可以列出最近一次匹配账本 `BUY` 之后的到期节点，供用户按平台记录勾选实际发生的申购，并逐笔核对金额、费用和成交净值日。
3. 用户明确确认后，同日多笔申购在一个事务中通过既有 `createTransactionRecord` 写入。场外基金份额未知时使用 `PENDING`：金额和净值日已知，份额/单价为空，必须关联现金结算腿；官方份额仍经基金确认工作台核对。
4. 服务端重新校验家庭作用域、计划日期、账户/基金归属、暂停申购规则和同日同账户同基金已有有效 `BUY`。任一笔失败时整批回滚；成功后一次重建受影响快照。
5. 快速录入仅支持限定账户且关联单只场外基金的计划。多候选资产计划不能凭计划确定实际买入哪只基金，仍需使用常规流水录入或外部账单导入。
6. 用户确认实际发生属于账本事实输入，不等于计划自动执行；不引入第二余额、交易状态表或自动交易服务。

## 兼容与回滚

- 不修改现有 schema 或历史交易。禁用快速录入入口即可回滚功能；已确认的 `BUY` 仍保留为正常账本流水，可按冲正协议修正。
- ADR-023 关于计划节奏、计划—实际核对和不自动下单的其他决策继续有效；只替代“定投页完全不提供交易录入”的边界。

## 验证

- 单测覆盖最近一次 BUY 后的未录节点、账户/基金过滤和当前日期边界。
- E2E 覆盖用户在定投页核对金额后批量录入、待确认基金流水与重复提示。
- 生产构建与账本现金联动、家庭作用域和审计链契约保持通过。
