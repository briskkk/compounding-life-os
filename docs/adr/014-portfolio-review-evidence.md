# ADR-014：组合复盘是派生证据与用户判断，不是第二套账本或自动建议

## 状态

Accepted。

## 背景

周期复盘需要解释本周、本月或本季度利润和亏损的来源，并把交易、时点和风险变化放回同一证据链。直接保存可编辑收益数字会违反“交易账本是唯一事实源”；自动生成结论又会重新引入 ADR-011 已移除的建议层。

## 决策

1. 复盘的组合收益、资产贡献、来源拆分、行为和风险均由交易流水、派生快照、PriceBar 与 RateBar 重算。
2. 金额归因使用“期末价值 − 期初价值 − 净资金流”；多期收益率贡献使用链接贡献，使贡献百分点合计回到组合 TWR。
3. 标的合计与组合之间的残差必须作为独立“待对账差额”展示，不得进入标的或资产类别排名；真实赎回在途资金属于资产状态，另行展示并明确不作为利润贡献。
4. `PortfolioReview` 只保存用户笔记、草稿/完成状态、作者和当时的只读指标快照；指标快照用于保留复盘语境，不参与持仓、余额、净投入或后续绩效计算。
5. 页面提供事实性回看，不生成买卖建议、规则结论或 LLM 解释。判断由用户写入复盘笔记。
6. 复盘记录属于家庭业务数据，受 Family scope、VIEWER 只读、PostgreSQL RLS 与审计链保护。
7. 进行中记录以家庭、周期类型和周期起日为身份；截至日随再次保存更新，因此本月/本季度草稿不会在第二天变成不可见的旧记录。

## 后果

- 历史行情或汇率补齐后，页面实时重算结果可能与已保存的证据快照不同；这是数据质量改善，不应反向改写账本。
- 完成状态不是财务结账锁，不阻止后续保存修订；每次保存或完成均追加审计记录。
- 若未来增加评论、清单或附件，应继续以用户输入为主，并保持派生指标只读。

## 验证

- 引擎单测验证资产金额、来源金额和链接百分点均与组合结果对账，并覆盖独立待对账差额、分红、费用、交易与风险变化。
- E2E 验证周期深链、归因维度切换、草稿持久化，以及桌面视口下资金数字不拆行、无页面级横向溢出。
