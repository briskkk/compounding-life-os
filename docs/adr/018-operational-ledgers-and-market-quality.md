# ADR-018：公司行动、基金规则与行情质量保持证据层和账本层分离

## 状态

Accepted。

## 背景

拆合股、换股、转托管、分红再投等事件会改变份额、成本或现金，但如果直接改持仓会绕过交易账本。基金销售规则与行情源质量同样需要长期留痕，但费率表、暂停公告、调用成功率和跨源价差都不应成为新的资产余额或自动投资决策。

## 决策

1. `CorporateAction` 是家庭作用域的事件证据包；实际数量、成本与现金影响必须展开为可冲正的 `Transaction`。内部 `SHARE_ADJUSTMENT` / `COST_ADJUSTMENT` 只允许由该流程生成。
2. CSV 导入保留原文件批次、列映射、逐行问题和语义指纹。有效行才能入账；跨文件重复行跳过，不通过覆盖或删除历史来“去重”。
3. `FundTradePolicy` 只保存用户根据基金公司或销售平台核验的申购费率、赎回阶梯和暂停申购窗口。费率只提供录入参考，实际费用由成交单确认；暂停窗口阻止普通 BUY，但红利再投资通过公司行动证据进入。
4. `MarketProviderDaily` 是全局观测表，按来源、能力和日期累计真实调用成功率、延迟及错误。人工跨源检查逐个取价并把结果追加到家庭 `AuditLog`；超过阈值只提示关注，不自动切换来源或改写 `PriceBar`。
5. 上述页面属于流水与健康中心的二级工作流，不增加桌面一级导航，也不为移动网页压缩；移动体验留给独立 App。

## 后果

- 持仓、成本、收益和现金继续完全由账本重放；事件、规则和质量指标不能反向覆盖财务事实。
- 公司行动可以整体冲正，原事件与生成流水仍可审计。
- 行情短时熔断与长期质量证据分离；观测写入失败不得拖垮行情主链。
- 基金特殊规则需要用户提供来源并定期复核，系统不声称自动同步全部基金公告。

## 验证

- 单测覆盖拆股成本守恒、成本调整、历史前复权、公司行动生成与冲正、CSV 映射/逐行幂等和基金规则边界。
- 双 schema、SQLite 迁移、PostgreSQL RLS/搬迁清单保持同步。
- `npm test`、`npm run build` 与 Playwright 全量作为交付门禁。
