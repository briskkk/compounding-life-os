# ADR-017：运行核对与确认使用追加证据，不建立第二账本

## 状态

Accepted。

## 背景

用户需要区分盘中估值与已结算快照，查看行情任务是否执行，并用券商、银行或基金平台账单核对账户余额和基金赎回到账。如果把外部余额或“已确认”状态写成可编辑资产余额，会绕过交易流水并形成第二事实源；如果只显示提示，则无法形成可追溯的处理闭环。

## 决策

1. 系统保留实时估值与最近可复核快照两条证据口径，实时数不覆盖历史快照。详细状态集中在健康中心；总览只显示一句数据结论，看盘以低权重状态行说明最新行情与最近完整收盘，账户页不重复展示技术口径。
2. 行情刷新与派生快照重建写入 `AuditLog`，健康中心以审计记录展示任务时间线；快照重建不修改交易流水。
3. 账户对账把外部账单余额、当时账本派生余额、差额、来源和日期作为 `RECONCILE` 审计凭证追加保存，不新增可写账户余额字段。当前版本只允许核对今日账本，避免用当前估值错误比较历史账单。
4. 基金赎回到账确认使用 `FUND_SETTLEMENT_CONFIRMED` 审计凭证；预计结算腿仍由原流水派生。实际金额或日期不一致时必须冲正并重录，不能用确认按钮覆盖金额。
5. 基金估算净值仍按 ADR-012/013 通过原流水冲正和官方净值替换闭环。

## 后果

- 所有财务数仍由交易、行情、负债和派生快照计算；核对凭证只提供可追溯证据。
- 同一账户可以追加多次核对，历史不会被覆盖。
- 健康中心可以提供安全修复动作，但不得自动补交易、改估值或修改目标配置。
- 审计日志同时承担业务审计与运行证据，任务详情必须保持可解析且避免写入密钥。

## 验证

- 单测覆盖实时覆盖率与最近完全结算快照选择。
- CI 使用一次性 PostgreSQL 16 数据库演练 schema、RLS 和跨家庭策略验证。
- E2E 共享种子家庭串行执行，避免并行写入污染核对口径。
