# ADR-027：跨市场收益按北京归属日归属

## 背景

此前跨市场组合按**交易所交易日**归属。美股一场（美东 D 日 09:30–16:00）实际发生在
北京 D 日 21:30 至 D+1 日 04:00/05:00，于是：

- 收益日历、快照和区间收益把北京次日凌晨才落定的收益记进北京 D 日那一格；
- 看盘在北京白天用「美东今天」判定当日盈亏，账户/持仓页却用北京日期比较同一个交易日字符串，
  同一持仓在不同页面时有时无（P1-26 的跨时区变体）；
- 06:30（北京）的美股收盘刷新任务在 UTC 日界下只能把美东 D 日写入 UTC D 日格，
  与用户在北京 D+1 上午打开页面时的直觉不一致。

用户已确认改为**按北京时间归属**：一场交易算在北京时间哪一天落定。

## 决策

1. 新增唯一归属判定 `src/lib/engine/portfolio-day.ts`：
   - `portfolioDayOffset(asset)`：美股（`US…`）为 +1，A 股 / 港股 / 场外基金为 0；
   - `attributionDateKey(asset, 交易所交易日)`：交易所交易日 + 偏移 = 北京归属日；
   - `liveAttributionDates / liveQuoteAttribution / livePreviousClose`：实时「今日涨跌」窗口与昨收基线的唯一入口。
2. **美股美东 D 日的行情计入北京 D+1**：`PriceBar` 仍保存真实交易所交易日；组合估值读模型
   （`loadPriceSeries`）把美股日线日期键平移 +1，日格（`computeWealthSeries`）按北京日历日切分，
   快照终点取北京今天。行情落库、数据健康与跨源价差核验仍使用真实交易所日期。
3. 实时口径统一：报价参与「今日涨跌」当且仅当其**北京归属日**属于允许窗口
   （北京今天；美股另含北京晚间 21:30 起正在进行、归属北京明天的那一场）。
   看盘、总览、持仓、账户、对账、移动端 API 全部改走 `dailyQuoteValuation` / `livePreviousClose`。
4. 实时叠加只在最新归属日 = 北京今天时落格，避免把归属明天的场次提前写进今天的财富轨迹与日历。
5. 估值证据字段（`latestValuationDate`、估值缺口 `valuationDate`）同样按北京归属日呈现，
   与所在日格同口径；真实交易所日期仍可从 `PriceBar` 与行情健康页读取。
6. 不做「按北京零点切开一场」：收益口径仍是收盘价对收盘价（一场一个观察点），
   只改变这一场落在哪一格。

## 后果

- 北京 D+1 那格 = 北京当日场次（A 股 / 港股 / 基金）+ 美东 D 日场次；北京 D 日格不再包含美股收盘后的行情。
- 06:30 美股刷新与 16:30 境内刷新都会把结果写进用户当天（北京）打开的日历格，实时口径与已结算口径一致。
- QDII 官方净值的 `navDate`、基金盘中估值与代理指数相关性拟合保持不变（见 ADR-005/006/013），
  本决策只覆盖交易所行情（股票 / ETF / 指数）在组合收益中的日期归属。

## 迁移与验证

- 无 schema 与数据迁移：`PriceBar` / `Snapshot` 结构不变；快照在下次行情刷新或写入时按新口径增量重建，
  也可在健康中心手动全量重建。迁移前保留 SQLite 在线备份的既有约定不变。
- 单测：`portfolio-day`（偏移、跨月跨年、实时窗口、有效昨收）、`daily-pnl`（美股归属与北京晚间场次）、
  `beijing-attribution`（真实 PriceBar → 快照 → 收益日历 → 单资产序列整链路：美东 01-05 计入北京 01-06，
  北京 01-05 沿用上一收盘且无收益观察）。
- 回归：`npm test`、`npm run build`、Playwright 全量。
