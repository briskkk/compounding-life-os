# ADR-023：定投计划只定义执行节奏，完成情况由交易账本派生

## 状态

Accepted。用户于 2026-09-11 确认开始实施定投管理与后续月结工作流；本 ADR 记录第一阶段的账本边界。

## 背景

真实账本中存在大量连续、小额、多渠道的 BUY。通用 `CashPlan` 能表达未来现金流，却不能表达候选资产、执行频率、计划金额和实际买入之间的关系。若计划直接生成交易，会把尚未发生的安排写进事实账本；若定投页另存实际完成金额，又会形成第二套投资事实。

## 决策

1. `InvestmentPlan` 保存计划名称、同币种每期金额、工作日/每周/每月节奏、起止时间和可选账户。
2. `InvestmentPlanAsset` 允许一条策略关联多只同币种候选资产，覆盖渠道限额下的替代执行；一只资产同一时点只属于一条有效计划。
3. 月度实际投入只从计划窗口内、候选资产和可选账户匹配到的有效 `BUY` 流水派生。待官方净值确认的基金 BUY 计入实际投入，并单独标记待确认笔数与金额。
4. 计划与 BUY 的关系是执行核对，不声称每笔买入由计划直接触发，也不改写流水、持仓、净投入或收益。
5. 工作日节奏只生成周一至周五节点，不冒充交易所开市日。结束计划保留历史；调整金额或候选资产应结束旧计划并新建版本。
6. 定投管理不连接券商、不自动下单、不生成流水、不做择时建议。收益继续由现有复盘引擎计算。
7. 两张计划表受 family scope、VIEWER 只读、PostgreSQL RLS 与审计链保护。

## 后果

- 用户可以按策略观察计划金额、截至今日应投金额、账本实际投入和待确认状态。
- 多只同币种替代基金可以合并为一条策略；跨币种资产必须拆成不同计划，避免使用当前汇率制造历史投入误差。
- 实际买入可以高于或低于计划，但页面只陈述差额和证据边界，不给出买卖指令。

## 验证

- 纯函数测试覆盖工作日、每周、月末、账户过滤、候选资产合并、待确认和计划结束。
- 双 schema、SQLite migration、家庭作用域、PostgreSQL RLS 与搬迁清单一致。
- E2E 覆盖创建计划、读取既有 BUY、结束计划和历史保留。
