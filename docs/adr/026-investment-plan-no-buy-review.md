# ADR-026：计划日未买入可由用户按日核对，不生成交易

## 背景

已到期而账本无 BUY 可能是漏录，也可能是实际未买。把两者都永久列为“待核对”会让工作日多基金计划的快速录入队列失去可用性；仅靠超期隐藏又不能说明用户已经核对。

## 决策

1. 新增 `InvestmentPlanDayReview` 保存用户明确确认的“该计划日未买入”，按家庭、计划和日期唯一。`revokedAt` 支持撤销并保留原证据；关键动作追加审计。
2. 同日核对表单可在一个事务中录入已勾选的实际申购，并确认未勾选基金当天确实未买。整日未买时无需生成任何 BUY 或刷新快照；两种结果分别要求明确勾选核对声明。
3. 服务端复核家庭权限、计划日、限定账户、单只基金和同日有效 BUY；已有 BUY 不能标记未买，重复确认不能静默覆盖。任一项失败整次核对回滚。
4. 已确认未买从快速录入队列移出，在逐日执行中显示独立状态。计划节点、本月应投金额和金额差额保留；账本实际投入、现金、持仓和收益不因该状态改变。
5. 若之后通过其他账本入口补录了该日 BUY，逐日状态以账本为准，并提示原未买确认与之冲突、可撤销；不自动改写审计证据。
6. 当前月较早的待核对日期折叠进历史，仍可由逐日格直接打开核对。不能把隐藏当成已确认未买。

## 迁移与验证

- SQLite 增量迁移、PostgreSQL 镜像、RLS、scoped DB、搬迁/清空清单同步；迁移前保留当前 SQLite 在线备份。
- 单测覆盖未买状态不改投入、撤销恢复队列、账本与未买证据冲突、混合提交声明及家庭只读权限。
- E2E 覆盖整日未买、旧日期入口、撤销和已有 BUY 拒绝误标未买。
