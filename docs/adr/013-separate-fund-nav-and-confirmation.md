# ADR-013：分离基金成交净值日与份额确认日

## 状态

Accepted；修订 ADR-012 中“QDII 顺延确认净值日”的部分。

## 背景

ADR-012 首版把 `navDate` 同时用于“采用哪一天的净值”和“份额何时确认可用”，并把 QDII 的 T+2 确认延迟错误地解释为净值日顺延。实际规则是：交易日 15:00 前受理的普通基金与 QDII 申赎均按 T 日净值成交；QDII 通常到 T+2 才完成登记确认，但确认延迟不改变成交净值所属日。

该混用导致 019671 在 2026-08-20 15:00 前卖出时，页面错误选择 2026-08-21 净值 1.3976，而不是 2026-08-20 净值 1.3981。

## 决策

1. `Transaction.navDate` 只表示成交净值所属日：15:00 前为 T 日，15:00 后或非交易日为次一交易日；QDII 不额外顺延。
2. 份额确认完成日由 `fundConfirmationDate(navDate, { qdii })` 确定性派生：普通基金近似 T+1，QDII 近似 T+2，不新增可写状态表或第二事实源。
3. `Position.availableQty` 与历史超卖校验使用派生确认日；净值查询、成交金额和页面净值预览使用 `navDate`。
4. 页面分开显示“成交净值日”和“预计确认日”，不再用“QDII · T+2”修饰净值日期。
5. 赎回到账日仍按既有 `settlementDate` 规则独立推算。
6. QDII 分类使用已核验基金代码注册表优先、名称标记兜底；分类注册表与行情估值代理表分离，避免“无法用 USNDX 估值”被误解为“不是 QDII”。

## 兼容性与迁移

- 不新增数据库字段或迁移；确认日可由 `navDate`、基金 QDII 属性与固定规则重建。
- 既有 QDII 流水若曾按旧规则写入顺延后的 `navDate`，需要通过冲正/重录修正，系统不静默改写历史账本。
- 普通基金、股票及既有现金结算腿口径不变。

## 验证

- 019671：2026-08-20 15:00 前 → `navDate=2026-08-20`、净值 1.3981；T+2 确认日为 2026-08-24（工作日近似）。
- 同日 15:00 后 → `navDate=2026-08-21`。
- QDII 申购在派生确认日前仍计入持仓但不可卖。
