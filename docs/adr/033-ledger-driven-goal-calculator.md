# ADR-033：默认使用账本驱动的目标测算，FIRE 降为退休压力测试

## 背景

原 `/goals` 同屏放入目标金额、退休支出与收入、提取率、通胀、退休年数、月投入、收益率、波动率、蒙特卡洛、Coast FIRE、多方案和储蓄录入。低频且假设密集的退休模型压过了用户真正需要回答的两个问题：按当前投入何时达标，以及指定日期需要每月投入多少。

原规则还允许 `STREAM` 退休目标使用 `NET_WORTH`，会把房产、员工持股等长期资产计入退休起点；储蓄记录不足三个月时也会产生“可持续投入”文案。两者都会制造不应有的确定感。

## 决策

1. `/goals` 的默认产品名改为“目标测算”。首屏只展示账本当前资本、目标金额与日期、计划月投入、预计达成时间、目标日所需投入、P10/P50/P90 三档结果，以及本金与预计复利增值拆分。
2. `LUMP_SUM` 普通财富目标仍可选择 `INVESTABLE` 或 `NET_WORTH`。本条原定的退休资本边界已由 ADR-034 替代。
3. 有可投资组合权重时，随机路径、确定性达标时间和页面展示统一使用资产类别模型推导的收益与波动；手工收益/波动只作为组合模型不可用时的兜底。
4. 少于 3 个有效收支月时标记“储蓄能力证据不足”，不生成可持续投入情景；3–5 个月为初步参考，6 个月以上为较充分证据。
5. 退休支出、稳定收入、提取率、退休年数、积累概率、退休期不断供概率和完整蒙特卡洛曲线进入折叠的“退休压力测试”。概率必须标明模型与路径数，不得解释为保证。
6. 临时试算不写库；只有用户点击“保存到主目标”并确认后才更新目标。默认界面只突出一个主目标，既有其他目标保留在高级管理区，不迁移或删除。
7. 目标测算退出一级侧栏，从总览目标卡片与命令面板进入。路由、`Goal` 表、投影引擎和移动 API 保持兼容。

## 兼容与回滚

- 不修改 Prisma schema，不迁移或删除既有 `Goal`、`SavingsEntry` 或审计数据。
- 回滚页面和导航不会影响目标记录；退休资本边界以 ADR-034 为准。
- 账本、实际投入、持仓、收益和储蓄记录均不由试算自动修改。

## 验证

- 单测覆盖目标资本口径，并回归投影与储蓄计算引擎。
- E2E 覆盖默认两问、三档结果、一级导航移除、命令面板入口、编辑弹窗与各宽度无页面级溢出。
- 运行 TypeScript、全量单测、生产构建和目标页定向 Playwright。
