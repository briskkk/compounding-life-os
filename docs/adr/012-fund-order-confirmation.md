# ADR-012：基金确认与在途资金建模（事件拆分，不引入状态表）

## 状态

Accepted

> 2026-08-23：其中“QDII 顺延确认净值日”的规则已由 [ADR-013](013-separate-fund-nav-and-confirmation.md) 修订。`navDate` 现表示成交净值所属日，T+1/T+2 确认完成日独立派生。

## 背景

场外基金交易与股票不同：申购按金额下单、按成交净值日折算份额；普通基金通常 T+1、QDII 通常 T+2 完成登记确认；赎回按份额/金额申报、资金 T+2~T+10 才到账。赎回在途期间资金既不在份额中（已申报冻结）也不在现金中（未到账）。

## 决策

1. **不引入"待确认/在途"可变状态表**。确认日与到账日是由「下单日 + 规则偏移」确定性推导的，"在途"始终是重放时的派生视图，任何时点可重算，永不与流水漂移。确认结果偏离预期（净值差异、到账延迟、赎回失败）用既有冲正/重录机制修正，而非状态机。
2. `Transaction` 增加三个可选列：`navDate`（成交净值所属日）、`navSource`（OFFICIAL / ESTIMATE，仅元数据）、`settlementDate`（预计到账日，缺省 = occurredAt 即时结算）。
3. **可用份额**：申购/转入按由 `navDate` 派生的确认完成日生效，赎回/转出按发生日即时冻结；`Position.availableQty` 由折叠派生，卖出校验与表单关联共用此口径。
4. **延迟结算腿**：基金赎回的现金结算腿发生在 `settlementDate` 而非成交日；申购现金腿仍即时（资金当日划出）。
5. **在途资金口径**：`pendingSettlementsAt` 派生「已申报 SELL 且结算腿尚未发生」的资金，并入净资产与可自由投资（即将成为现金）；总览页展示每笔在途的申报日与预计到账日。
6. **录入辅助**：基金申购支持按金额录入（金额 ÷ 成交净值/盘中估算 → 预计份额，净值未知则拒绝静默落库）；卖出自动带出当前/可用份额与净值；15:00 临界、确认完成日与到账日由 `src/lib/engine/fund-order.ts` 分开推算（工作日近似，不含法定节假日）。
7. 基金「金额 = 份额 × 净值」校验放宽到份额两位小数舍入容差（±0.05 元级）；股票等其余资产保持原有严格容差。

## 原因

- 状态表会成为第二事实源，与 ADR-001（账本唯一事实源）和 ADR-010（快照可重建）冲突。
- 事件拆分 + 派生视图让净资产在「份额 → 在途 → 现金」全程连续，现金口径在到账前不提前增加。

## 后果

- 快照重放在在途期间并入在途资金；到账日之后现金腿自然生效，无需额外迁移。
- 冲正一笔延迟赎回会级联作废其结算腿（沿用 `settleOfId` 机制）。
- 交易日历为工作日近似，法定节假日不建模（与系统既有行情口径一致）；费率（申购费/赎回费折扣）与分红方式未建模，「金额 = 份额 × 净值」因此保留小额误差说明。
- Web（tx-form）与移动端（RecordSheet + FundOrderRules.swift）共用同一确认推算口径。
