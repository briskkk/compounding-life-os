# ADR-032：定投资产占用按账户判定，并支持批量建立独立计划

## 背景

ADR-023 规定“一只资产同一时点只属于一条有效计划”。这条限制没有区分托管账户，导致同一基金或 ETF 在不同平台分别执行时无法建立两条计划。创建入口也只面向单条策略：家庭需要给多只资产设置相同节奏时，必须重复填写日期、账户和频率。

真实 BUY 本来就同时带有 `accountId` 与 `assetId`。只要计划明确限定账户，两条同资产计划可以按账户分别匹配到账本，不会重复认领同一笔流水。

## 决策

1. 有效计划的资产占用由“资产”改为“资产 + 账户范围”：同一资产可以在不同的明确账户各有一条有效计划；同一资产、同一账户仍拒绝重复。
2. 未限定账户的计划覆盖该币种的所有账户，因此与该资产的任一明确账户计划互斥；反过来，资产已有未限定账户计划时，也不能再创建明确账户计划。这个保守边界避免同一笔 BUY 被两条计划同时计入。
3. 创建与编辑使用同一冲突规则。冲突提示必须指出已有计划的账户与名称，便于用户定位并调整。
4. 新增“批量独立计划”创建方式：用户一次选择多只同币种资产，共享节奏、日期、账户和说明，并可为每只资产覆盖默认金额；服务端在一个审计事务中为每只资产创建一条独立 `InvestmentPlan`。
5. 批量创建不是多候选策略。每条计划只关联一只资产、默认使用资产名称，因此可以独立编辑、结束，并继续满足单基金快速核对的前提。原“候选资产策略”创建方式继续保留，用于渠道限额下的替代执行。
6. 执行列表按限定账户分组；未限定账户的计划单列“全部同币种账户”。分组只改变展示顺序，不改变月度计划、实际 BUY 匹配、完成率或收益口径。
7. 计划仍不自动下单、不自动生成流水、不改变余额、持仓或收益。批量创建的每条计划都追加独立审计记录。

## 兼容与回滚

- 不修改数据库 schema，也不迁移或合并既有计划。既有未限定账户计划继续保持广域匹配，并按新规则阻止重叠。
- 可以移除批量入口并恢复旧冲突查询完成代码回滚；已创建的独立计划仍是合法的现有模型数据，可继续逐条维护。
- ADR-023 的计划—账本边界及 ADR-024/025/026 的用户确认、补录和未买证据规则继续有效。

## 验证

- 严格 TypeScript 与生产构建覆盖批量 Server Action、账户范围冲突查询和账户分组渲染。
- 隔离 E2E 覆盖：一次创建多条独立计划、每资产金额覆盖、同一资产跨账户创建成功、同一资产同账户重复被拒绝、计划按账户归类。
