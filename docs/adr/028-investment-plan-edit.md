# ADR-028：定投计划支持编辑，只影响未来计划节点

## 背景

ADR-023 只定义了「创建计划」与「结束计划」。用户调整每期金额、执行节奏、限定账户或候选资产时，只能结束旧计划再新建：审计里多出一条无意义的结束记录、`InvestmentPlan.startDate` 被重置、历史节奏被切断，历史完成率的分母也随之改变。结果是用户倾向不改计划，让计划数据与自身实际策略逐渐脱节。

同时，计划页的「实际投入 / 完成率」依赖 `startDate`、`cadence`、`scheduleDay`、`amount`——这些都是计划侧参数，不参与任何账本推导。因此允许编辑它们不会改动账本、现金、持仓或收益口径，风险边界与 ADR-023 一致。

## 决策

1. 新增 `updateInvestmentPlan` 写路径：可改名称、每期金额、执行节奏、执行日、开始日期、结束日期、限定账户、候选资产与说明。
2. **只影响未来计划节点**：编辑不重写历史。已发生的 `Transaction`、已存在的 `InvestmentPlanDayReview` 与既有审计记录一律不变；历史计划日的状态继续由账本照旧判定。
3. 修改后的节奏对**当月起**生效：`startDate` 不作为「向后兼容旧节奏」的分界，因为计划模型只保存一套当前节奏。页面必须如实说明「节奏自保存起生效」，不假装能还原旧节奏。
4. 服务端在写入前重新校验家庭作用域、候选资产存在性与类别（STOCK/FUND/ETF/GOLD）、同币种约束、账户币种一致、结束日不早于开始日，以及**候选资产未被其他有效计划占用**（与创建同一规则，排除自身）。
5. 编辑是账本事实之外的计划层操作，不生成交易、不改现金、不引入第二余额表；关键变更追加审计，写明变更前后的关键字段。
6. 账户变更不做历史流水迁移：若真实执行账户从 A 换到 B，历史流水仍属于 A，新节点按 B 匹配。这保证「账本记录实际、计划描述意图」的边界不被打破。

## 兼容与回滚

- 不修改 schema、不迁移历史数据。禁用编辑入口即可回滚；已编辑的计划保留最后一次取值。
- ADR-023/024/025/026 关于节奏、计划—账本核对、用户确认批量录入与未买证据的决策继续有效。

## 增补（2026-09-17）：区间未买

计划页新增 `recordInvestmentPlanNoBuyWindow`：在连续日期区间内一次确认「这些计划日没有执行」。
它是 ADR-026 未买证据的**批量录入方式**，不改变模型：每个计划日仍写入一条可撤销的
`InvestmentPlanDayReview`，仍不改现金、持仓、收益与计划额。差异只有两点：

1. 服务端按区间逐日复核，**已有有效 BUY（同一候选资产 + 计划限定账户）或已核对的节点如实跳过并不报错**，
   返回值分别给出写入数与跳过数，页面在提交前就预告「将标记 N 个、跳过 M 个」。
2. 未到期日期整批拒绝，避免把未来计划日提前标成未执行。

## 验证

- 单测覆盖字段校验、资产占用冲突、同币种与账户币种约束。
- E2E 覆盖通过界面编辑金额与节奏、保存后逐日节点按新节奏重算、历史已录入日状态不变、审计新增一条记录。
