# 家庭财富工作台 UI 设计规范

状态：已确认，实施中
版本：1.0
日期：2026-09-28
交互预览：[index.html](./index.html)

## 1. 产品目标

新界面帮助家庭依次回答四个问题：家底如何、投资发生了什么、哪些记录需要补齐、距离目标还有多远。所有页面遵循“结论 → 解释 → 证据”，避免让方法说明、低频设置或技术状态抢占首屏。

这次改版是信息架构与视觉系统迁移，不改变任何财务事实。交易流水仍是持仓、余额和绩效的唯一事实源。

## 2. 不可破坏的语义

- 家庭净资产 = 全部资产 − 负债；可自由投资资产只包含现金、可交易资产、黄金和在途资产。
- 总览不得把可投资组合的当日盈亏描述成家庭净资产的当日变化。
- 投资表现展示金额、周期、TWR / XIRR 含义、估值日期与覆盖状态。
- 计划只定义节奏。实际投入只来自有效 BUY；“未买入”是可撤销的核对证据。
- 待确认基金不能猜净值或份额。金额保留在在途，官方净值与平台份额核对后再确认。
- `PARTIAL`、`CLOSED`、`NO_UPDATE`、`FLOW_ONLY`、待确认、在途和已结算不能合并成一个“正常”状态。
- VIEWER 的只读边界、家庭作用域、审计链与冲正机制保持不变。

## 3. 信息架构

### 一级任务

| 入口 | 首要问题 | 核心页面 | 二级页面 |
| --- | --- | --- | --- |
| 总览 | 家里现在什么情况？ | `/` | 数据待办、目标入口 |
| 资产 | 钱在哪里，结构如何？ | `/positions` | 账户、负债、资产目录、配置目标、资产详情 |
| 投资 | 今天和过去赚亏多少？ | `/watch` | 收益历史、基准比较 |
| 记录 | 哪些事实需要录入或核对？ | `/transactions` | 定投、资金日历、导入、基金确认 |
| 复盘 | 结果从哪里来，下一期看什么？ | `/review` | 月结、长期复盘、决策库 |
| 目标 | 何时达标，每月需要投入多少？ | `/goals` | 情景试算、退休压力测试 |

### 低频工作流

数据健康、账户对账、基金确认、公司行动、基金规则、导入批次、行情质量、审计和设置通过以下入口出现：

1. 全局搜索；
2. 与事实状态相关的页面待办；
3. 侧栏底部“数据状态”；
4. 页面内上下文链接。

低频入口不消失，也不在一级导航中反复占位。

## 4. 全局壳层

- 侧栏：桌面 218px；1360px 以下 196px；1180px 以下使用抽屉。
- 顶栏：76px，包含面包屑、全局搜索、行情刷新、主题、家庭切换和个人入口。
- 内容区：最大 1600px；桌面左右边距 34px，1360px 以下 24px。
- 默认浅色；深色保留，使用同一语义 token，不为深色维护第二套布局。
- 一级导航活动态使用浅蓝底和蓝色图标文字，不使用发光线。
- 页面标题直接使用任务名，如“交易流水”“定投管理”；解释句放在标题下方。

### 形状与排版

- 正文采用系统无衬线中文字体；金额与对齐数字继续用 JetBrains Mono。
- 页面标题 28–35px；区块标题 15–18px；正文 14px；最小辅助文字 12px。
- 圆角继续使用现有 `xs / sm / md / lg / pill` 五档，不新增散落值。
- 页面面板只有一层细边框和极轻阴影；浮层使用既有 `--shadow-pop`。
- 颜色不能单独表达状态，必须同时提供文字、图标、符号或数值。

## 6. 页面设计

### 总览

首屏顺序：家庭净资产 / 可自由投资资产 / 负债 → 周月季投资表现 → 结果桥 → 财富轨迹与待办 → 资产构成与目标。

- 净资产不再紧邻没有范围说明的“今日盈亏”。
- 待办只展示可处理事项，点击直达基金确认、定投核对或账户对账。
- 数据完整时压缩为一行证据；存在缺口时展示受影响资产和处理入口。
- 安全储备只有在支出证据和储备范围明确后才能出现。

### 资产

- 默认“持仓明细”，以表格为主；结构分析、账户与负债、配置目标为同域二级视图。
- 默认列：资产、账户、市值、未实现盈亏、权重、估值依据。
- 数量、成本、当日盈亏通过列配置或资产详情提供。
- 点击资产进入详情或侧边预览；关闭后保留筛选、排序和滚动位置。
- 在途资产单列，不伪装成已确认持仓。

### 投资

- 顶部使用“今日 / 历史”模式。
- 今日：可投资组合实时估值、当日盈亏、纳入/未纳入数量、分时曲线、贡献与拖累、实时估值表。
- 历史：区间收益、TWR、XIRR、基准、回撤、波动率、收益日历。
- 今日口径与历史结算口径不能静默混合。

### 记录

- 默认交易流水；定投核对、资金日历和导入记录为二级模式。
- 单笔新增使用抽屉或独立工作区；CSV 导入保持独立批量流程。
- 提交前显示账户、币种、现金影响、日期、净值或份额状态。
- 成功后保留筛选并定位新记录；修改财务事实使用冲正。

### 定投核对

- 首屏优先显示待核对日期和节点数量。
- 每项必须明确选择“实际买入 / 实际未买入 / 稍后核对”。
- 已买入输入金额、费用和净值日；未买入不生成流水；稍后核对保留待办。
- 计划按账户分组；已结束计划进入紧凑归档。

### 复盘

- 保留结果、归因、行为与风险、结论四步。
- 步骤顶部常驻周期、收益、净投入和证据状态。
- 月结以四步进度组织，并提供“继续下一项”。
- 用户判断分为已确认事实、我的判断、下期验证；不自动生成买卖建议。

### 目标

- 一级入口回答“什么时候达标”“每月需要投入多少”。
- 当前资本、目标、达成日期、月投入和三档结果同屏。
- 情景试算即时预览但不写库；明确保存后才更新主目标。
- 退休压力测试继续位于高级区域，披露长期资产、负债和模型假设。

### 数据与治理

- 健康中心按“影响 → 原因 → 可执行修复 → 证据”排列。
- 正常状态不占据大片首屏；异常按对财务结果的影响排序。
- 所有修复入口继续执行权限、家庭作用域和审计校验。

## 7. 组件契约

| 组件 | 必须支持 |
| --- | --- |
| `AppShell` | 六项导航、面包屑、搜索、抽屉侧栏、主题和家庭切换 |
| `PageHeader` | 任务名、短说明、最多一个主动作和必要辅助动作 |
| `MetricStrip` | 2–5 个同层指标、范围标签、来源或周期 |
| `EvidenceLine` | 日期、覆盖、来源、异常入口；正常时保持低权重 |
| `TaskList` | 事项名称、数量、证据摘要、明确目的地 |
| `DataTable` | 列头排序、空状态、长名称、大金额、横向滚动边界 |
| `Drawer` | 焦点约束、Esc / 遮罩关闭、焦点归还、提交前影响预览 |
| `StatusTag` | 文字与语义色并用，不显示内部枚举 |

## 8. 完整状态

每个页面必须覆盖：加载、空数据、错误、部分证据、陈旧或缺失估值、只读、在途、待确认、长名称、大金额和键盘使用。写操作还必须覆盖字段错误、业务冲突、重复提交和提交后返回上下文。

## 9. 验收

- 1280、1440、1600、1920px：核心金额不截断，主任务不溢出，表格表头可理解。
- 560、640、700、800、1100px：页面级无横向溢出；宽表可在自身容器滚动。
- 键盘可完成导航、搜索、筛选、抽屉和表单；焦点清楚可见。
- 浅色、深色主题均满足语义色对比度；图表使用 CSS token。
- 总览、看盘和复盘中的同名金额必须能解释口径、周期和估值时点。
- 样式迁移不得改变引擎数值、数据库、API 和审计链。
