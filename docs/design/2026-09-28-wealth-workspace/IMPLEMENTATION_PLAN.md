## 每阶段固定步骤

1. 先读取路由、视图模型、引擎和现有 E2E；不从高保真演示复制假数据。
2. 先保留语义与所有状态，再迁移层级和样式。
3. 只使用现有 token 与共享组件；新增 token 先写入设计规范和守卫。
4. 先跑相关单测，再跑 TypeScript、构建和目标页面 Playwright。
5. 更新本计划状态与 `context/CURRENT_STATE.md`，记录真实完成范围。

## Phase 1 变更边界

- 新导航只改变入口归类，不迁移路由。

## 风险

- 旧 E2E 对导航组、面包屑和目标入口有显式断言，需要随 ADR-035 更新。
- `globals.css` 历史样式量大，后续页面优先收敛已有规则，避免只靠文件尾覆盖无限增长。
- 复盘与目标页面需让周期上下文持续可见，同时保持复盘事实、用户判断和目标试算的写入边界。
- 目标重新进入一级导航只改变发现性，不允许恢复复杂 FIRE 首屏。
- 复盘常驻上下文条与结果步的「结果可用性」会同时出现对账、估值覆盖与在途状态：前者是跨步骤的常驻证据，后者是结果自身的可用性说明，两者同源同值，不是两套口径；若后续要求单一来源，应删除结果步那一行而不是让上下文条变成第二个事实源。
