# Compound Life 中文用语与字体

界面用语参考证券和基金产品的惯用表达，但最终以本项目的计算定义为准。标题、字段和按钮简洁；范围、时点与异常保留在数字附近；完整定义通过说明和明细提供。以下为设计候选，尚未修改正式应用。

## 参考与取舍

- [天天基金持仓收益说明](https://help.1234567.com.cn/weixin/q_1222.html)将持仓收益定义为持仓市值与持仓成本之差，清仓后重置；未确认申购不计入持仓份额。这支持持仓与在途分开呈现，但不等于本产品所有收益都应称“持仓收益”。
- [富途持仓设置](https://www.futuhk.com/hans/manual/topic11_106)区分成本价计算方式和盘前、盘后参考价。相同短标签可能有不同计算口径，不能仅因行业常用就直接替换本项目定义。
- [富途账户及持仓说明](https://www.futuhk.com/hans/support/topic2_176)在期货账户中明确区分未实现和已实现盈亏。本项目沿用这种术语区分，但不会引入其期货计算方式。

因此，本产品保留“投资收益”“未实现盈亏”“当日盈亏”三类名称，不合并成模糊的“收益”。

## 首屏字段

| 概念 | 设计用语 | 必须保留的含义 |
| --- | --- | --- |
| 全部资产减负债 | 净资产 | 含房产和长期资产；说明中列范围 |
| 未扣负债的全部资产 | 总资产 | 不称净资产或账户余额 |
| 现金及可交易资产加在途 | 可投资资产 | 不含房产、华为长期持股及其他不符合项目分类的资产 |
| 全部负债余额 | 负债 | 与总资产、净资产分列 |
| 持仓页当前市值合计 | 持仓总市值 | 该页含房产，不含在途；不是可投资资产 |
| 所选周期的投资结果 | 投资收益 | 期末减期初再减外部净投入；不直接用净资产增减替代 |
| 组合外部流入减流出 | 净投入 | 排除内部买卖、内部转账及结算腿 |
| 时间加权收益率 | 组合收益率 TWR | 衡量组合表现；“时间加权”放在说明 |
| 实际现金流体验 | 资金加权收益率 XIRR | 不与 TWR、简单收益率混用；按现有 XIRR 实现解释 |
| 当前持仓市值减剩余成本 | 未实现盈亏 | 不等于累计投资收益，也不含已卖出部分的盈亏 |
| 已卖出部分的盈亏 | 已实现盈亏 | 依据账本，不由当前持仓倒推 |
| 当前行情归属日的组合损益 | 当日盈亏 | 标“可投资组合”；实时值另标“实时估算”及覆盖范围 |
| 申购待确认与赎回待到账 | 在途资金 | 已计入可投资资产，不伪造份额；不能再加一次到资产总额 |
| 按当前汇率折算 | 人民币折算 | 保留原币金额或价格；不称历史成交汇率 |

“期初 / 期末 / 净投入 / 投资收益”可在明确标为可投资组合的同一区域内使用短名。离开该上下文时，恢复“期初可投资资产 / 期末可投资资产”。

## 交易与核对状态

| 场景 | 设计用语 | 不使用的表达 |
| --- | --- | --- |
| 录入真实发生的交易 | 录入流水 | 记一笔、立即投资、执行买入 |
| 确认基金登记份额 | 确认份额 | 下单、买入成功 |
| 份额尚未确认 | 份额待确认 | 未买入、交易失败 |
| 卖出后资金尚未到账 | 赎回待到账 | 交易未完成（过于宽泛） |
| 到期但尚无核对证据 | 待核对 | 未执行、漏投 |
| 已核实当天没有买入 | 已核对未买入 | 失败、已跳过（原因不明） |
| 流水已写入账本 | 已记录 | 已结算（若尚未取得结算证据） |
| 确有结算证据 | 已结算 | 已更新（不能表达结算状态） |
| 查询取得了新值 | 已更新 | 数据正常（范围不明确） |
| 来源日期落后 | 待更新 | 缺失（有旧值时不准确） |
| 取得来源失败，保留旧值 | 更新失败，保留原值 | 已刷新、已完成 |
| 从未取得可用估值 | 暂无估值 | ¥0.00、无收益 |
| 按当前报价或模型估算 | 实时估算 / 盘中估值 | 官方净值、已结算 |
| 基金正式公布净值 | 官方净值 | 实时价格 |
| 用户维护的估值 | 手动估值 | 最新行情 |
| 只读成员 | 只读 | 无权限（过于笼统） |
| 纠正已记录的财务事实 | 冲正 | 删除（不能暗示物理删除） |

保留“存入 / 取出”和“转入 / 转出”的账本类型区别，不为统一文案将不同交易类型合并。按钮用动词加对象，例如“保存草稿”“确认份额”“导出持仓”。

## 标题与说明缩写

| 当前或前稿 | 设计建议 | 原因 |
| --- | --- | --- |
| 家庭财富总览 | 总览 | 品牌和家庭身份已在壳层显示 |
| 资产与持仓 | 资产 / 持仓明细 | 页面与二级视图分别命名 |
| 财富轨迹 | 净资产走势 | 当前图画的是净资产，明确指标 |
| 本月表现 | 本月投资表现 | 补足“投资”，与净资产变化区分 |
| 收益 | 投资收益 | 避免与未实现盈亏、分红混淆 |
| 基金份额 | 基金份额待确认 | 任务标签保留状态，单独“份额”不表达任务 |
| 定投记录 | 定投记录待核对 | 不让计数看起来像全部历史记录 |
| 账户对账 | 账户待对账 | 用于待办；功能页标题仍为“账户对账” |
| 目标日可能落在哪里 | 目标日资产情景 | 当前该区展示 P10/P50/P90 金额，不是日期 |
| 保守区间 / 基准中位 / 乐观区间 | 较低情景 P10 / 中位情景 P50 / 较高情景 P90 | 金额分位点不是三个完整区间，也不是收益保证 |
| 本金和复利各贡献多少 | 本金与收益构成 | 减少问句；收益可能为负 |
| 预计复利增值 | 预计投资收益 | 避免负值仍被称为“增值” |
| 这次测算用了什么 | 测算依据 | 短标题，不增加口语问句 |
| 既有其他目标 | 其他目标 | 去除重复修饰 |
| 回退/模拟 | 成本估值 / 模拟数据 | 实际单项保留来源区别；汇总可用“其他来源”并可展开，不把真实回退估值当模拟 |

目标页的 P10/P50/P90 用语基于 `src/app/goals/page.tsx` 中 `finalPoint.p10/p50/p90` 经 `fmtCNY` 输出的现状。此处只提出文案修正，不修改模型和概率。

## 文字规则

1. 页面标题一般 2–6 个字，字段一般 2–8 个字。准确性优先，不强行为满足字数而删掉“未实现”“待确认”等限定。
2. 同一概念固定一个名称；区间、币种和范围在分区标明，不在每个字段重复。
3. 一条状态说明只说当前事实和下一步，例如“净值更新失败，保留11月25日估值”。
4. 空值用“—”并给原因；真实零值正常显示。正负金额显示符号，金额和比例不可只靠红绿区分。
5. 核心范围、时点和异常不能只在悬停时出现；完整公式可进入说明。
6. 定投是计划，流水是事实；“核对完成”不等于“已买入”。

## 字体候选

原附件 `app/layout.tsx` 没有引入自定义字体，`globals.css` 只导入 Tailwind。预览所用 Tailwind 的默认栈以 `-apple-system / BlinkMacSystemFont / Segoe UI / Roboto` 开头，因此原模板不是已指定的 Inter 或 Geist。

| 编号 | 组合 | 选择依据 |
| --- | --- | --- |
| A | 模板系统字体 | 最接近附件的默认实现；实际字形随设备而变 |
| B | Inter + 苹方 SC | 适合以 Mac 为主的使用环境；更容易比较数字和英文的变化 |
| C | Geist + 苹方 SC | 作为更紧凑、偏现代产品界面的备选 |
| D | Inter + Noto Sans SC | 中文也使用开源 Web 字体，便于不同平台保持一致 |

B、C 在没有苹方的设备上回退至 Noto Sans SC；不会把回退字形称为苹方。Inter 和 Geist 主要改变英文、数字与符号，不会凭空改变中文笔形。字体差异是设计判断，不代表某一款客观上“更高级”。

本轮固定字号与字重对照，正文 14px，标题 24px，金额 31px 上限，常用字重 400 / 500。金额启用等宽数字特性，不把等宽代码字体铺满中文界面。精确响应字号以交互稿为准。

[Inter 官方介绍](https://rsms.me/inter/)说明其界面使用与等宽数字特性；[Geist 官方介绍](https://vercel.com/font)说明其设计取向；[Noto CJK 官方仓库](https://github.com/notofonts/noto-cjk)提供中文字体来源。预览内嵌公开字体子集及 OFL 许可，不安装系统字体；正式实施还需确定完整字体加载与自托管方案。

## 确认范围

先确认字体、页面布局和关键中文名称。随后将此用语表映射到 `wealth-scope.ts`、`labels.ts` 和各页面，结合财务计算与权限状态验收；本轮未修改这些正式代码。

用户已确认字体 D（Inter + Noto Sans SC）并授权启动正式前端改造。字体决策已确认，具体实现与回归结果以项目当前状态记录为准。
