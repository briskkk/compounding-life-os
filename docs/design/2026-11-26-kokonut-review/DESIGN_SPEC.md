# Compound Life 前端重新设计

建议沿用附件的中性配色、规整列表、细分隔线与统一图标，移除当前胶带、虚线、标题涂鸦和彩色偏移阴影。保留六项家庭任务导航和现有财务语义，通过字号、间距与对齐建立层级，让总览结果和持仓明细更早进入首屏。

本稿供设计确认。正式的 `design.md`、ADR、应用样式、路由、计算和写入流程均未替换。图片是视觉概念，金额为演示数据；精确财务与交互约束以本规范为准。

## 用户明确修订

- 品牌统一为 **Compound Life**。
- 字体贴近原模板的克制无衬线效果，减少粗黑、大字号和全页加粗。
- 界面文案简洁：页面标题“总览”，区块“本月表现”“待核对”；说明优先收进帮助与明细，只保留范围、缺口和状态等必要文字。
- 本次只修订设计交付，正式应用品牌与样式待确认后实施。

## 三个候选方向

三个候选以同一总览和同一组演示值比较，避免不同数据干扰选择。每张是独立完整桌面画面。区别在阅读顺序，而非简单换色。

| 候选名称 | 结构 | 长期使用侧重点 |
| --- | --- | --- |
| 清晰账面 | 顶部三项家底；整行月度投资结果；下方趋势与待办 | 默认建议，家庭财富和投资绩效边界最直观 |
| 趋势与行动 | 顶部紧凑家底；大面积财富轨迹；右侧持续显示核对事项；底部月度结果 | 更快看长期变化与今天需要处理的事 |
| 紧凑工作台 | 家底单行摘要；区间结果和待办并排；下方紧凑趋势与资产明细列表 | 高频使用，减少纵向滚动，更多数字同屏比较 |

候选编号以聊天中实际展示顺序为准。三者都保留六项导航，默认浅色，不新增业务模块；图片中的演示曲线与数值不作为财务输出。

## 共享视觉规范

### 布局与字号

- 设计基准 1440 × 1024；正式验收范围 1280 / 1440 / 1600 / 1920px。
- 侧栏 224px；收起后 64px；顶栏 64px；内容左右间距 32px，1280px 时可降至 24px。
- 布局间距以 4px 为基础，模块间 24px，模块内 20–24px。列表 / 表格常规行高 56px，长名称自动增加，不截断关键金额。
- 页面标题 22/30px；区块标题 15/24px；正文与表格 14/22px；说明 13/20px；图表刻度最低 12px。
- 核心金额 30px，次级金额 26px，常用字重 400–500。等宽数字，金额右对齐，币种和精度遵循现有格式化工具。
- 字体已确认 D：英文与数字使用 Inter，中文使用 Noto Sans SC，由应用自托管。标题和金额不使用粗黑字重，400–500 为主。
- 普通容器 10px 圆角，按钮 6px，输入 6px；分隔线 1px；常态无阴影，弹层才使用柔和阴影。
- 不增加纸纹、渐变、玻璃、胶带、旋转、硬边彩色阴影或装饰性英文。

## 页面信息架构

一级导航仍为总览、资产、投资、记录、复盘、目标。二级导航使用细下划线或浅灰选中背景，主导航使用黑底白字。低频治理从数据状态与搜索到达，设置在侧栏底部。家庭切换、搜索、主题与行情刷新保留，顶栏不重复长口径说明。

| 页面 / 工作流 | 首屏优先信息 | 次级信息与动作 |
| --- | --- | --- |
| 总览 | 净资产 / 可投资资产 / 家庭负债；本期收益 / 净投入 / TWR | 结果桥、财富轨迹、待核对；构成与目标入口随后出现。财富金额不带模糊的“较上期增长”收益暗示 |
| 持仓 | 二级导航、紧凑统计、筛选、完整明细表 | 保留名称、账户、数量、成本、现价与来源、市值、当日与未实现盈亏、权重、流动性；来源附着现价，长名称换行，在途单列。表格是主界面 |
| 看盘 | 北京归属日、当日损益与实时估算状态、分时曲线 | 贡献 / 拖累和实时估值列表；异常贴近受影响数字，缺分时不画假曲线 |
| 流水 | 时间 / 账户 / 类型筛选和有效流水列表，主动作“记录流水” | 录入按需展开；导入入口指向原导入页，冲正历史可展开；不照搬模板的付款、充值按钮 |
| 定投核对 | 本月与视图筛选，每条计划一行，待核对优先 | 默认展示实际 / 到期、计划金额、下一日与操作；逐日证据按需展开，明确已买入 / 已核对未买 / 待核对 |
| 复盘 | 周期与四步导航、结果摘要、证据状态 | 归因、行为、判断随步骤展开；笔记区保留事实 / 我的判断 / 下期验证；无自动投资建议 |
| 目标 | 当前资本、预计达成、所需月投入，三档情景 | 临时试算与正式保存区别清晰，高级压力测试折叠；不更改已有目标采用的财富口径 |
| 月结 / 治理 | 先给缺项或异常、影响范围与处理入口 | 完成记录压缩，完整证据按需展开，不用整页绿色成功卡片遮蔽少量异常 |
| 账户 / 设置 | 紧凑列表与当前分区；当前家庭和权限可见 | 低频编辑按需展开；危险操作保留确认词和影响范围，不因换皮减少保护 |

持仓完整列允许容器内水平滚动，名称列可固定。1280px 不通过删除财务证据来强行塞下所有列；同一名称和金额不得双重省略。金额是否显示到分沿用现有规则，悬停不是获得关键金额的唯一方式。

## 交互与状态规范

| 状态 | 呈现与处理 |
| --- | --- |
| 正常 / 已结算 | 数字、范围与时点同行或就近；有确定证据才显示“已结算” |
| 部分估值 | 金额旁说明覆盖和缺口，提供明细入口，曲线保留断点或对应状态 |
| 过期估值 | 显示真实来源日期和受影响资产，不以刷新按钮点击时间替代行情时间 |
| 完全缺失 | 金额用“—”和原因，不用 ¥0.00 代替未知；提供补充记录或重试 |
| 基金在途 | 已计入资产但不伪造份额，确认、部分、未知和赎回未到账不合并 |
| 只读成员 | 保留查看与导出；不呈现可用的录入 / 确认 / 保存，说明只读角色 |
| 加载 | 骨架占据结果或表格原位置，减少跳动；遵守项目已有路由加载限制 |
| 错误 | 区域内显示失败原因和重试，不能把失败后的旧数字标为最新 |
| 空数据 / 无筛选结果 | 区分首次建账和筛选无结果，分别给录入入口或清除筛选 |
| 长名称 / 大金额 | 名称换行，金额完整；高密度表格局部滚动，页面本身不溢出 |
| 键盘 | 可见蓝色焦点；排序状态、输入标签、对话框焦点约束与归还保留 |
| 窄屏 | 侧栏抽屉、单列内容、表格内部横滚；不另做移动端产品架构 |

周期、筛选、排序继续使用 URL 状态。成功反馈只在实际提交成功后出现；批量确认继续显示范围、笔数与影响，不因视觉简化省略确认。

## 确认后的实施与验收边界

先确认方向，再用所选方向细化持仓、看盘、定投及深色关键页。待页面和状态稿确认后，按壳层与 token → 总览 → 资产 → 投资 → 记录 → 复盘 / 目标 / 治理分批改造。每一批可独立检查与回滚。

正式变更时更新 `design.md` 与相关上下文。若进一步改变六项导航或已接受语义，再走 Proposed ADR 和用户确认流程；本稿没有修改 accepted 决策。

实施验收须包括财务范围与时间、URL 与权限、键盘操作、双主题和正式桌面尺寸。UI/API 变更按仓库要求运行 `npm test`、`npm run build`、`npm run test:e2e`。本轮交付设计文档与独立原型；原型验证不代表正式业务应用已完成改造。
