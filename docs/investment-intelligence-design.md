# Investment Intelligence / 长期投资复盘设计

## 1. 结论

这项功能值得加入 Portfolio，但不应另做一个脱离账本的“AI 投资顾问”。正确形态是扩展现有 `/review`：

- `周期复盘`：保留现有日、周、月、季证据链。
- `长期复盘`：回答五年真实成绩、年度路径、资产与基金贡献。
- `决策库`：把账本交易组织成可复核的决策事件，分析追涨、卖出后表现、持有不对称、换手和费用。
- `假设实验`：用显式规则运行反事实路径，比较“实际路径”和“如果当时按另一条规则执行”。

首版只做确定性计算、数据质量门槛和事实性回看。AI 只在这些能力稳定后作为可选解释层加入，不计算指标、不填补缺失数据、不生成买卖建议，也不写入账本。

这不是从零开始。现有系统已经具备长历史重放、TWR、Modified Dietz、XIRR、回撤、波动率、金额/链接百分点归因、交易后区间表现、换手、费用、历史月份、证据快照和审计链。本设计的重点是补齐跨年范围、基金子组合口径、行为统计、决策语境和严格反事实。

## 3. 产品边界

### 3.1 默认分析范围

长期复盘默认使用 `基金子组合（FUND_SLEEVE）`，而不是整个可投资组合。

三种范围必须明确区分：

1. `INVESTABLE_PORTFOLIO`：现金和所有可交易资产；只有家庭外部 DEPOSIT/WITHDRAW 是外部现金流。
2. `FUND_SLEEVE`：所有基金资产；基金 BUY 是子组合资金流入，SELL/现金分红是资金流出，现金不属于基金子组合。
3. `ASSET`：单只基金；该基金的申购、赎回和现金分红是该标的的投资者现金流。

若没有这层区别，“五年基金收益”会被现金、ETF 或其他资产污染，TWR/XIRR 也会使用错误的现金流边界。

### 3.2 要回答的问题

- 五年实际投入、赎回、费用、当前价值和投资收益分别是多少？
- TWR 与 XIRR 分别是多少，差异来自哪些资金时点？
- 哪些基金、策略桶和市场贡献了收益或亏损？
- 买入前 20/60 个交易日的走势与买入规模有何关系？
- 卖出后 30/90/180 个交易日发生了什么？相对基准如何？
- 盈利和亏损持有是否存在稳定的不对称？
- 费用、换手、基金切换和现金等待造成了多少可核验损耗？
- 在明确假设下，实际路径与不操作、按原始配置投入、定投指定基准等路径相差多少？

### 3.3 明确不做

- 不给出“应该买/卖哪只基金”的自动建议。
- 不把模型生成文字当作财务事实、行为诊断或风险偏好结论。
- 不从历史操作直接推断用户的真实风险偏好；只陈述实际暴露和观察到的行为。
- 不把 XIRR − TWR 直接命名为“操作 Alpha”。二者回答的问题不同。
- 不把卖出后上涨直接判定为“卖错”。事后路径忽略了风险、资金用途和替代投资。
- 不为了分析新增可写持仓、余额或累计收益表。
- 不把历史归档聚合资产拆成不存在的基金明细。

## 4. 指标口径

### 4.1 五年真实成绩

长期页同时展示金额和收益率，顺序固定：

```text
期初基金价值
+ 区间基金净投入
+ 基金投资收益
= 期末基金价值
```

其中：

- 基金净投入 = 申购金额 + 申购费 − 赎回到账 − 现金分红。
- 基金投资收益 = 期末基金价值 − 期初基金价值 − 基金净投入。
- TWR：按有效估值观察点剔除基金子组合现金流后链式计算，衡量基金组合路径。
- XIRR：使用实际申购、赎回、现金分红和期末价值，衡量资金体验。
- Modified Dietz：只保留为短周期近似和曲线展示；长期总结果优先使用 XIRR。
- 最大回撤：基于有效估值序列；同时显示高点、低点、恢复日和最长未恢复区间。

GIPS 的解释同样强调：TWR 用于移除外部现金流影响，MWR/IRR 反映现金流的时点和规模。产品必须保留这两个不同问题，而不是合成一个“真实收益率”。

### 4.2 归因

按成熟度分两层：

#### P0：可对账的实际贡献

- 单只基金金额贡献。
- 策略桶/市场/主动被动的金额贡献。
- 市场净值变化、现金分红、费用、待对账差额。
- 所有金额贡献合计必须回到基金子组合投资收益。
- 所有链接贡献百分点合计必须回到基金子组合 TWR。

#### P2：相对政策基准的主动归因

需要每个资产具有带有效期的基准与分类后，再计算：

```text
实际组合 TWR − 政策基准收益
= 配置效应 + 选基效应 + 交互效应 + 费用/执行 + 未归属残差
```

采用逐日 Brinson-Fachler 思路并做多期链接。自定义标签可以交叉观察，但不能作为总归因分区；分类缺失的资产进入“未分类”，不能被分摊到其他桶。

### 4.3 行为指标

#### 买入前发生了什么

每个 BUY 事件保存或重建以下“当时可见”特征：

- 基金前 20/60 个交易日收益。
- 对应基准前 20/60 个交易日收益。
- 基金在过去 1/3/5 年滚动净值中的分位，仅使用事件日前数据。
- 买入金额占事件前基金子组合和总可投资资产的比例。
- 买入后 30/90/180 日基金及相对基准收益。

页面先展示散点与分桶统计，不先下“追涨”结论。少于 5 个合格事件时不生成定性标签；样本更多时仍展示样本数、覆盖率和置信区间。

#### 卖出后发生了什么

每个 SELL 事件显示：

- 卖出时相对移动平均成本的盈亏状态。
- 卖出后 30/90/180 个交易日基金收益和基准超额。
- `未满观察期`、`净值缺失`、`基金终止/合并` 等删失状态。
- `卖出份额 × 事后基金路径` 的持有差额，只命名为“事后持有差额”。

不能只统计继续上涨的次数，也不能把未满 180 日的近期卖出当作 0。

#### 盈亏持有不对称

Portfolio 的会计成本是移动平均法，不应为了行为分析改成 FIFO。首版使用两个不改变会计口径的代理指标：

- 完整持仓段：从账户+资产数量由 0 变正，到再次回到 0；比较盈利/亏损持仓段的持续时间。
- 卖出倾向：在卖出时按移动平均成本判断盈利/亏损，比较盈利仓与亏损仓的卖出比例和部分减仓幅度。

页面名称使用“盈亏持有不对称”，并说明它是处置效应的代理观察，不宣称心理原因。

#### 交易强度与成本

- 年化换手率。
- 交易次数与月度活跃度。
- 申购/赎回费的金额与占平均资本比例。
- 基金数量、短期往返交易、切换候选。
- 现金等待天数，仅在资金去向能够可靠关联时计算。

### 4.4 观察画像，不是性格画像

长期页可以生成“观察到的投资行为”，但每个结论都必须带：

- 观察区间。
- 合格样本数 / 总事件数。
- 数据覆盖率。
- 指标定义。
- 稳定性或置信区间。
- 无法排除的替代解释。

建议字段：

- 实际最大基金仓位与最大回撤。
- 基金集中度路径。
- 买入前涨跌分布。
- 盈利/亏损卖出不对称。
- 年化换手和费用拖累。
- 计划内/临时决策比例（只有用户补录意图后才显示）。
- 已记录规则遵守率（只有存在用户规则时才显示）。

不输出“风险偏好：中高”“止损能力：弱”等貌似确定、实际缺乏可验证定义的标签。

## 5. 决策事件

### 5.1 自动事件与用户语境分离

每笔有效 BUY/SELL 都可以派生一个默认事件；派生事件不是新事实表。只有用户补充以下语境或组合多笔流水时才持久化：

- 这是计划内、定投、再平衡、临时反应还是资金需要。
- 当时依据和预期持有周期。
- 触发条件和风险边界。
- 哪些 SELL 与 BUY 构成一次基金切换。
- 下次复查日期。

系统可以提出“疑似切换”候选，例如同账户三日内发生相近金额的 SELL 和 BUY，但必须由用户确认，不能自动建立因果关系。

### 5.2 建议数据模型

```text
InvestmentDecision
  id, familyId, decidedAt, kind
  intent, thesis, expectedHorizonDays
  ruleReference, reviewAt, note
  reconstructionStatus  // CONTEMPORARY | RECONSTRUCTED
  evidenceSnapshotJson  // 当时市场证据，非财务事实源
  authorId, createdAt, updatedAt

InvestmentDecisionTransaction
  decisionId, transactionId, role
  // ACTION | SOURCE | TARGET

AssetAnalysisProfile
  id, familyId, assetId
  effectiveFrom, effectiveTo
  managementMode        // ACTIVE | PASSIVE | UNKNOWN
  marketRegion, strategyBucket
  benchmarkSymbol
  sourceName, sourceReference, verifiedAt
```

约束：

- `InvestmentDecisionTransaction` 只引用账本，不复制金额、份额或价格。
- 决策记录可以删除/修改其文字，但不能修改关联流水；所有修改进入审计链。
- 历史补录的理由标记为 `RECONSTRUCTED`，不能冒充当时记录。
- 基准与分类带有效期，避免用今天的基金定位解释五年前。
- 派生结果不建永久事实表；若性能需要缓存，必须由账本哈希、行情水位和算法版本共同失效。

## 6. 反事实实验

“如果五年什么都不操作”必须先被定义，不能只删除所有交易。首批提供四个版本化模板：

### A. 冻结起始持仓

- 从起始日真实持仓开始。
- 忽略之后的主动 BUY/SELL。
- 外部新增资金留在现金；取款先从现金扣除，不足则情景失败。
- 分红留在现金，公司行动照常应用。

回答：如果保留原持仓、之后不主动操作，会怎样？

### B. 按起始权重投入

- 从起始日真实持仓开始。
- 每笔外部新增资金按起始基金权重，在下一可交易净值日投入。
- 赎回按同一权重处理。
- 交易费按用户选择的真实费率或零费率情景计算。

回答：如果只维持最初的选择和比例，会怎样？

### C. 定投指定基准

- 使用与实际相同的外部现金流日期和金额。
- 全部投入用户选择的可获得基准或基准基金。
- 明确成交延迟、费用、分红再投和汇率规则。

回答：如果这些钱只按相同节奏投入一个基准，会怎样？

### D. 用户目标配置

- 使用 `AllocationTarget` 的目标、容忍带和再平衡频率。
- 只模拟，不生成订单。
- 每个再平衡动作使用当时可得价格，不允许未来数据。

回答：如果按自己事先定义的配置纪律执行，会怎样？

### 6.1 输出命名

主指标命名为“决策路径差额”，不是“操作 Alpha”：

```text
决策路径差额 = 实际期末价值 − 情景期末价值
```

同时显示实际/情景的 TWR、XIRR、最大回撤、费用和现金占用。除非已有政策基准和严格主动归因，否则 `alpha` 只用于组合相对基准收益，不用于泛指所有操作效果。

### 6.2 公平比较契约

每次运行必须保存或展示：

- 起止日期与起始持仓。
- 现金流集合。
- 价格/净值/汇率水位。
- 分红、费用、公司行动和执行延迟规则。
- 缺失数据与失败日期。
- 情景模板版本和算法版本。

任一关键规则无法执行时返回 `PARTIAL` 或 `BLOCKED`，不自动用 0、当前价格或事后已知数据填补。

## 7. 信息架构与交互

### 7.1 路由

不增加一级导航。保留“复盘”为一级入口，使用内部横向模式导航：

```text
/review                         周期复盘（现有）
/review/history                 长期复盘
/review/decisions               决策库
/review/scenarios               假设实验
```

长期复盘默认范围为“基金子组合 · 成立以来”，允许选择自然年、近五年和自定义区间。

### 7.2 长期复盘桌面线框


“决策时间带”是本页唯一高视觉权重元素：使用现有天空蓝组合曲线、不同方向和文字的买卖标记，以及灰色数据缺口带；选中事件再使用蓝色描边。买卖动作不复用涨跌颜色，避免把“买入”等同于正面、把“卖出”等同于负面。它不是装饰；它把市场路径、用户行为和证据完整性放在同一时间坐标上。

### 7.3 决策库

默认是可筛选表格而不是卡片墙：

| 日期 | 事件 | 标的 | 金额 | 事件前 60D | 之后 90D | 相对基准 | 语境 | 资格 |
| --- | --- | --- | ---: | ---: | ---: | ---: | --- | --- |

点击一行打开右侧详情，不跳离时间轴：

- 账本原始流水与审计入口。
- 事件前可见证据。
- 30/90/180 日观察结果。
- 关联切换交易。
- 用户当时记录与事后补录的明确区分。
- “加入本期复盘”只引用事件，不复制财务数字。

### 7.4 假设实验

使用“实际路径”与一个情景对比，默认不允许同时堆叠多个情景。左侧固定规则摘要，右侧显示终值差额、路径、回撤和费用。改变任何规则后立即把结果标为“新情景，尚未保存”；保存只保存参数和证据水位，不保存为真实资产结果。

## 9. 数据质量门槛

首屏不是一个笼统的“数据完整率”，而是每类分析的资格矩阵：

| 分析 | 必需输入 | 不满足时 |
| --- | --- | --- |
| 真实收益 | 起止价值、子组合现金流、有效净值 | `BLOCKED`，不显示收益率 |
| 单基金贡献 | 交易、份额、价格/净值、汇率 | 缺失部分进入待对账差额 |
| 买入前走势 | 事件前至少 20/60 个有效净值点 | 该事件从对应统计排除 |
| 卖出后表现 | 之后 30/90/180 个交易日净值 | 标记未满观察期，不计为 0 |
| 选基相对收益 | 有效期内基准映射与基准序列 | 不展示选基效应 |
| 切换效果 | 用户确认 SOURCE/TARGET 交易关系 | 只显示疑似切换，不计算结论 |
| 处置效应代理 | 卖出时移动平均成本和完整持仓段 | 展示样本不足或不可计算 |
| 反事实 | 全部规则需要的价格、现金流和公司行动 | `PARTIAL/BLOCKED`，不填补未来信息 |

每个指标返回统一证据元数据：

```ts
type EvidenceStatus = 'ELIGIBLE' | 'PARTIAL' | 'BLOCKED'

interface MetricEvidence {
  status: EvidenceStatus
  eligibleCount: number
  totalCount: number
  coveragePct: number | null
  asOf: string
  ledgerWatermark: string
  priceWatermark: string | null
  methodVersion: string
  limitations: string[]
}
```

## 10. AI 解释层

### 10.1 放置顺序

AI 不是首版依赖。只有当长期结果、行为统计和反事实引擎通过守恒测试后，才增加“解释这份证据”按钮。

### 10.2 输入与输出

输入只包含用户明确选择的聚合证据包，不默认发送原始流水、账户名称和自由文本笔记。界面显示提供方、模型、证据日期和即将发送的数据范围。

输出必须通过结构校验：

```ts
interface ReviewExplanation {
  observations: Array<{
    text: string
    evidenceIds: string[]
    limitation?: string
  }>
  hypotheses: Array<{
    text: string
    evidenceIds: string[]
    howToVerify: string
  }>
  questions: Array<{
    text: string
    evidenceIds: string[]
  }>
}
```

限制：

- 每句话必须引用一个或多个确定性证据 ID。
- AI 不返回数字字段，不允许在文本里新增未出现在证据包中的数值。
- 不输出具体买卖、仓位或基金推荐。
- 不自动保存。用户点击“采纳到我的笔记”后，内容才作为用户选择进入复盘笔记与审计记录。
- AI 不可用时，整个长期复盘、决策库和假设实验仍完整可用。

本边界需要 [ADR-021](adr/021-investment-intelligence-evidence-boundary.md) 获得确认后才能实施；在此之前 ADR-011 仍然有效。

## 11. 技术架构

### 11.1 新增纯引擎

```text
src/lib/engine/investment-history.ts
  基金子组合现金流、跨年结果桥、年度/月度分桶、最长回本

src/lib/engine/decision-events.ts
  交易 → 派生事件、持仓段、切换候选

src/lib/engine/behavior-analysis.ts
  事件前后窗口、样本资格、行为统计

src/lib/engine/counterfactual.ts
  版本化情景重放、守恒、失败状态

src/lib/engine/active-attribution.ts      // P2
  有效期基准、Brinson-Fachler、跨期链接
```

所有引擎保持纯函数，不依赖 Prisma、React 或网络。

### 11.2 查询与 API

```text
src/lib/investment-intelligence-data.ts
  family scope 查询、行情/汇率装配、证据水位、View Model

GET /api/reviews/history
GET /api/reviews/decisions
POST /api/reviews/scenarios/run        // 只读计算，不保存
POST /api/reviews/scenarios            // 保存参数，需要真实用户会话
POST /api/reviews/explain              // P3，可选 AI
```

GET 可沿用会话优先、全局只读 key 回落；所有保存、决策标注和采纳操作必须使用真实用户会话，并保持 VIEWER 只读。

### 11.3 性能

当前约 59k 基金净值点、530 个买卖事件，按日期 Map 预索引后可以在请求内确定性计算，不需要首版新增物化结果表：

- 单次加载后按 `symbol → date → nav` 索引。
- 事件窗口使用交易日索引，不为每个事件重复扫描完整序列。
- 反事实按需运行，只计算一个实际路径和一个情景。
- 若实测超出页面预算，再增加由 `ledger hash + price watermark + method version` 键控的可删除缓存。

## 12. 分期

### P0：五年真实成绩与资格门槛

- `/review/history` 与基金子组合范围。
- 成立以来/自然年/近五年/自定义区间。
- 金额桥、TWR、真正 XIRR、年度/月度收益、回撤和恢复期。
- 标的/策略/市场实际贡献与显式残差。
- 数据资格矩阵和归档资产隔离。
- 不新增数据库模型，不接 AI。

验收：金额与 TWR 守恒；缺失净值不造收益点；历史结果不混入当前报价；归档桶不进入基金级行为统计。

### P1：决策库与行为证据

- 30/90/180 日事件窗口。
- 买入前 20/60 日走势。
- 完整持仓段、盈亏持有不对称、换手与费用。
- `InvestmentDecision`、关联表和有效期资产分析档案。
- 用户确认切换候选与补录当时语境。

验收：不使用事件日之后的数据构造事件前特征；近期事件正确删失；移动平均成本不被行为分析改写。

### P2：假设实验与主动归因

- 四个版本化反事实模板。
- 目标配置情景。
- 有效期基准映射。
- 配置/选基/交互/费用/残差归因。

验收：所有情景使用同一初始状态与现金流；无前视；公司行动、费用、分红和汇率规则显式；任何差额可追到日级事件。

### P3：可选 AI 证据解释

- 用户主动触发。
- 聚合、最小披露证据包。
- 证据 ID 强绑定、Zod 校验、失败完整降级。
- 只有用户采纳后才进入笔记。

验收：AI 无法写账本、保存指标或调用交易；关闭模型配置时核心功能不受影响；模型新增数字或无证据结论被拒绝。

## 13. 测试重点

- 基金子组合 BUY/SELL/费用/分红现金流符号与守恒。
- TWR、Modified Dietz、XIRR 名称和数值不互换。
- 多币种按事件日和估值日历史汇率折算。
- PENDING 申购、赎回在途、休市、无更新和部分覆盖。
- 冲正、公司行动、合并/终止基金、内部结算腿不重复计流。
- 同日多笔交易的稳定排序与事件分组。
- 前 20/60 日特征严格无前视。
- 30/90/180 日使用交易日且正确处理观察期不足。
- 反事实的初始持仓、现金流、费用和终值逐日守恒。
- SQLite/PostgreSQL 双 schema、RLS、搬迁与审计链。
- 1280/1440/1600/1920px 无页面级横向溢出；表格只在局部横向滚动。

## 14. 需要确认的产品选择

实施前只需要确认三件事：

1. 长期复盘是否默认分析“全部基金”，还是默认只分析“当前仍持有过的可识别基金”，把三个历史归档桶完全排除在结果桥之外？本设计建议前者：归档桶进入组合总结果，但不进入基金级行为分析。
2. 首个反事实是否选择“冻结起始持仓”还是“定投指定基准”？本设计建议先做“冻结起始持仓”，因为它对额外基准映射依赖最少。
3. 是否接受 Proposed ADR-021 的 AI 边界？不确认也不影响 P0–P2；P3 保持不实施。
